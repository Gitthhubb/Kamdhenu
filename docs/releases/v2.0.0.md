# Kamdhenu 2.0.0

**Release date:** 24 November 2026

## Highlights

- Account-level milkman/supplier catalogue with an independent default rate per supplier.
- Milk-entry form prefills the selected supplier's rate. A new supplier is remembered with the rate first recorded; an existing configured default is not overwritten by a one-off rate change.
- Milk-type defaults and per-litre rates remain configurable alongside shifts, transaction kinds, transaction counterparties and expenditure categories.
- Custom transaction kinds are included in monthly totals according to their configured accounting effect and retain their configured display labels.
- Firestore rules accept validated custom catalogue keys and record label snapshots while preserving UID ownership and append-only milk/transaction records.
- Backups validate supplier rates/catalogue structure before writes and preserve custom options through restore.
- CSV export emits a real UTF-8 BOM, CRLF rows, correctly quoted cells and formula-injection protection.
- PWA cache version is incremented so installed clients replace the older application assets.

## Data compatibility

Existing account records and historical ledger rows are not rewritten. Previously saved milkman names are migrated into supplier suggestions from the account profile and the records available in the local cache; historical record labels remain as originally stored. Supplier-specific rates are not inferred from old milk rates: the first subsequent entry for a supplier with no configured rate establishes that supplier's default.

## Required deployment action

After the Render v2.0 deployment, publish the repository's updated firestore.rules in the Firebase Console for the Firebase project configured in Render. The previous deployed rules reject current record label fields and custom catalogue keys. Until the new rules are published, Firestore may reject otherwise valid v2.0 writes. No Firestore production rules can be published through the connected GitHub/Render operations.

## Verification

GitHub Actions runs the complete Node test suite, Vite production build and high-severity npm audit. The final release is conditional on those checks passing and on publication of the updated Firestore rules.
